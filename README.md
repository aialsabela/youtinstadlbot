# ربات دانلودر یوتیوب، اینستاگرام، تیک‌تاک و توییتر/ایکس

ربات تلگرامی حرفه‌ای برای دانلود ویدیو از یوتیوب، اینستاگرام، تیک‌تاک و
توییتر/ایکس، ساخته‌شده با [yt-dlp](https://github.com/yt-dlp/yt-dlp)
(رایگان و متن‌باز، بدون هیچ API پولی).

## قابلیت‌ها
- دانلود ویدیوی یوتیوب با **انتخاب کیفیت** (بهترین، 1080p، 720p، 480p، 360p)
- دانلود **فقط صدا (MP3)** از ویدیوهای یوتیوب
- دانلود پست یوتیوب/اینستاگرام/تیک‌تاک/توییتر (عکس، ویدیو، ریل)
- پشتیبانی از **پست چندرسانه‌ای** (چند عکس/ویدیو در یک پست - اینستاگرام
  carousel یا توییت چندعکسی - به‌صورت آلبوم)
- پشتیبانی از پست‌های خصوصی (با کوکی)
- **عضویت اجباری در کانال** قبل از استفاده از ربات - با دستور `/setchannel` هر
  وقت خواستی کانال رو عوض کن، بدون نیاز به ریدیپلوی
- صف دانلود و محدودیت نرخ درخواست، مناسب اجرا روی سرور رایگان

## ساختار پروژه

```
ytbot/
├── bot.py              # هندلرها، کیبورد انتخاب کیفیت/MP3، صف دانلود، مدیریت خطا
├── downloader.py        # لایه‌ی دانلود: مدیریت کوکی + کیفیت/فرمت + چند کلاینت یوتیوب
├── config.py             # همه‌ی تنظیمات از متغیرهای محیطی
├── export_cookies.py     # اسکریپت کمکی برای گرفتن کوکی مستقیم از مرورگر
├── requirements.txt
├── .env.example          # نمونه‌ی متغیرهای محیطی لازم
├── Procfile / railway.json / nixpacks.toml / render.yaml   # فایل‌های دیپلوی
└── runtime.txt
```

### چرا این معماری؟
- **`config.py`**: همه‌ی تنظیمات یک‌جا و از env var، بدون مقدار hardcode توی کد.
- **`downloader.py`**: یوتیوب گاهی یک کلاینت (مثلاً وب) رو بلاک می‌کنه ولی کلاینت
  دیگه (اندروید/iOS/تی‌وی) کار می‌کنه؛ این ماژول به‌ترتیب چندتا رو امتحان می‌کنه و
  خطاهای دقیق (بلاک‌شدن، خصوصی‌بودن، حجم زیاد) رو جدا تشخیص می‌ده. کیفیت ویدیو
  یا حالت فقط-صدا (MP3) هم از همین‌جا کنترل می‌شه.
- **`bot.py`**: وقتی لینک یوتیوب می‌رسه، اول یه کیبورد اینلاین با گزینه‌های کیفیت
  و MP3 نشون داده می‌شه؛ انتخاب کاربر با یه توکن کوتاه (نه خود لینک کامل، چون
  `callback_data` تلگرام محدودیت حجم داره) به دانلود واقعی متصل می‌شه. صف دانلود
  (`Semaphore`) و محدودیت نرخ درخواست هر کاربر (`cooldown`) هم داره تا سرور
  رایگان زیر بار سنگین نخوابه.

## نصب و اجرای لوکال

```bash
pip install -r requirements.txt
cp .env.example .env
# مقدار BOT_TOKEN رو توی .env پر کن
python bot.py
```

روی سیستم باید `ffmpeg` هم نصب باشه (برای merge کردن ویدیو و صدا):
```bash
# اوبونتو/دبیان
sudo apt install ffmpeg
# مک
brew install ffmpeg
```

## ساخت ربات در تلگرام
1. به [@BotFather](https://t.me/BotFather) پیام بده.
2. `/newbot` رو بزن، اسم و یوزرنیم دلخواه رو وارد کن.
3. توکن رو کپی کن و توی `BOT_TOKEN` بذار.

## حل خطای "Sign in to confirm you're not a bot"

یوتیوب IP سرورهای ابری (Railway, Render, AWS و...) رو معمولاً به‌عنوان ربات
تشخیص می‌ده. راه‌حل: کوکی یک حساب گوگل واقعی رو به ربات معرفی کن.

**⚠️ توصیه می‌شه از یک حساب گوگل فرعی/تستی استفاده کنی، نه حساب شخصی اصلی.**

### مرحله ۱: گرفتن کوکی از مرورگر

**⚠️ نکته‌ی مهم:** کوکی مخصوص یک حساب کاربری واقعیه؛ هیچ ابزاری (از جمله این
ربات) نمی‌تونه کوکی رو از بیرون "پیدا" یا بسازه. باید از مرورگر خودت، بعد از
لاگین با اکانت خودت (ترجیحاً یه اکانت فرعی/تستی، نه اکانت شخصی اصلی)، استخراج
بشه. دو روش داری:

**روش الف - با اسکریپت (بدون نیاز به افزونه):**
```bash
pip install yt-dlp --break-system-packages
python export_cookies.py chrome   # یا firefox, edge, brave, opera
```
قبلش با اکانت موردنظر توی همون مرورگر وارد youtube.com، instagram.com و در
صورت نیاز tiktok.com / x.com شو، و
**قبل از اجرای اسکریپت مرورگر رو کامل ببند** (وگرنه فایل کوکی مرورگر قفله و
قابل خوندن نیست). این اسکریپت خروجی `cookies.txt` رو کنار خودش می‌سازه.

**روش ب - با افزونه‌ی مرورگر:**
1. افزونه‌ی **[Get cookies.txt LOCALLY](https://chromewebstore.google.com/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc)** رو روی کروم نصب کن.
2. با اکانت گوگل موردنظر وارد youtube.com شو؛ با اکانت اینستاگرام موردنظر هم
   وارد instagram.com شو (می‌تونن دو اکانت جدا باشن).
3. روی آیکون افزونه کلیک کن و گزینه‌ی **Export All Cookies** (نه فقط تب فعلی)
   رو بزن تا کوکی هر دو دامنه با هم توی یک فایل `cookies.txt` ذخیره بشه.

### مرحله ۲: تبدیل به base64 (روش امن - پیشنهادی)
به‌جای اینکه فایل کوکی رو مستقیم توی گیت‌هاب بذاری (که خطر لو رفتنشه)، محتواش رو
base64 می‌کنیم و به‌صورت یک متغیر محیطی می‌ذاریم:

```bash
# لینوکس/مک
base64 -w0 cookies.txt

# ویندوز (PowerShell)
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cookies.txt"))
```

خروجی (یک رشته‌ی طولانی) رو کپی کن.

### مرحله ۳: تنظیم متغیر محیطی
توی Railway/Render، متغیر محیطی زیر رو اضافه کن:

```
COOKIES_B64=<همون رشته‌ی طولانی>
```

ربات موقع اجرا خودکار این مقدار رو دیکد کرده و به‌عنوان کوکی به yt-dlp می‌ده —
هیچ فایل حساسی توی گیت‌هاب کامیت نمی‌شه.

> روش جایگزین (کم‌توصیه‌شده): می‌تونی فایل `cookies.txt` رو مستقیم کنار `bot.py`
> بذاری و متغیر `COOKIES_FILE=cookies.txt` رو ست کنی — ولی در این حالت حتماً ریپو
> باید **Private** باشه.

### نکات مهم درباره‌ی کوکی
- کوکی‌ها بعد از چند هفته تا چند ماه منقضی می‌شن؛ اگه دوباره خطای مشابه اومد،
  مراحل بالا رو تکرار و مقدار `COOKIES_B64` رو آپدیت کن.
- استفاده‌ی زیاد از یک حساب گوگل برای دانلود ممکنه باعث محدودیت موقت اون حساب بشه؛
  به همین دلیل حساب فرعی توصیه می‌شه، نه حساب شخصی.

## دیپلوی از طریق گیت‌هاب

### چرا کلادفلر نه؟
Cloudflare Workers محیط V8/جاوااسکریپت با محدودیت زمان اجراست و به پایتون،
subprocess یا فایل‌سیستم واقعی دسترسی نداره، پس نمی‌تونه `yt-dlp`/`ffmpeg` رو
اجرا کنه. باید از پلتفرمی استفاده کنی که ماشین واقعی پایتون بده: **Railway** یا
**Render**.

### مرحله ۱: آپلود روی گیت‌هاب
```bash
cd ytbot
git init
git add .
git commit -m "Professional Telegram YouTube/Instagram downloader bot"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

### مرحله ۲: دیپلوی روی Railway (پیشنهاد اول)
1. برو [railway.app](https://railway.app) و با گیت‌هاب لاگین کن.
2. **New Project → Deploy from GitHub repo** → ریپو رو انتخاب کن.
3. توی تب **Variables** این متغیرها رو اضافه کن:
   - `BOT_TOKEN`
   - `COOKIES_B64` (طبق راهنمای بالا)
   - در صورت نیاز: `MAX_CONCURRENT_DOWNLOADS`, `USER_COOLDOWN_SECONDS` و بقیه‌ی
     مقادیر `.env.example`
4. Railway خودکار `railway.json` و `nixpacks.toml` (که ffmpeg رو هم نصب می‌کنه)
   رو می‌خونه و دیپلوی می‌کنه.
5. توی لاگ‌ها دنبال خط `Bot starting...` بگرد.

### مرحله ۳: دیپلوی روی Render (جایگزین)
1. برو [render.com](https://render.com)، با گیت‌هاب لاگین کن.
2. **New → Web Service** → ریپو رو انتخاب کن (`render.yaml` تنظیمات پایه رو
   خودکار می‌خونه).
3. متغیرهای محیطی بالا رو توی بخش Environment وارد کن.
4. دیپلوی کن.

## محدودیت‌های مهم

- **حجم فایل**: ربات‌های تلگرام معمولی (بدون Local Bot API Server) نمی‌تونن
  فایل بالای ۵۰ مگابایت بفرستن. برای فایل بزرگ‌تر باید
  [Local Bot API Server](https://github.com/tdlib/telegram-bot-api) خودت رو
  راه‌اندازی کنی (حد مجاز تا ۲ گیگابایت می‌ره).
- **لینک خصوصی/محدود**: ویدیوی خصوصی یا محدود به کشور خاص قابل دانلود نیست، حتی
  با کوکی.
- **اینستاگرام**: پست تکی (عکس، ویدیو، ریل)، پست چرخشی (چند عکس/ویدیو در یک
  پست - به‌صورت آلبوم توی تلگرام ارسال می‌شه، حداکثر ۱۰ آیتم چون محدودیت خود
  تلگرامه)، و پست‌های خصوصی (با کوکی) پشتیبانی می‌شن. اینستاگرام این روزها حتی
  برای پست‌های عمومی هم زیاد کوکی می‌خواد؛ اگه خطای ورود گرفتی، بخش کوکی رو
  دنبال کن.
- استوری (`/stories/`) معمولاً بعد از ۲۴ ساعت منقضی می‌شه و فقط تا قبل از انقضا
  قابل دانلوده.
- yt-dlp مرتب آپدیت می‌شه چون یوتیوب/اینستاگرام گاهی ساختارشون رو عوض می‌کنن. برای
  اینکه سرور همیشه آخرین نسخه رو داشته باشه (نه نسخه‌ی کش‌شده‌ی build قبلی)، فایل‌های
  `nixpacks.toml` (Railway) و `render.yaml` (Render) یک مرحله‌ی جدا دارن که هر بار
  build، فارغ از کش، `yt-dlp` رو force-upgrade می‌کنه.
- اگه با خطای `Requested format is not available` مواجه شدی برای **همه‌ی** فرمت‌ها
  (حتی MP3)، معمولاً یعنی نسخه‌ی yt-dlp نصب‌شده قدیمیه و نمی‌تونه رمزگذاری فرمت‌های
  یوتیوب رو باز کنه. توی لاگ‌های سرویس، خط `yt-dlp version: ...` رو چک کن؛ اگه با
  [آخرین نسخه‌ی منتشرشده](https://github.com/yt-dlp/yt-dlp/releases) فرق زیادی
  داشت، یه ریدیپلوی دستی (Redeploy) بزن تا مرحله‌ی force-upgrade دوباره اجرا بشه.

## عضویت اجباری در کانال

اگه بخوای کاربرها قبل از استفاده از ربات عضو یک کانال تلگرامی خاص بشن:

### مرحله ۱: پیدا کردن آیدی عددی خودت (برای ادمین ربات)
به [@userinfobot](https://t.me/userinfobot) پیام بده تا آیدی عددیت رو بهت بده.

### مرحله ۲: تنظیم متغیرهای محیطی
```
REQUIRED_CHANNEL=@channelusername
ADMIN_USER_IDS=آیدی_عددی_خودت
```
اگه کانال خصوصیه (یوزرنیم عمومی نداره)، به‌جاش آیدی عددیش رو بذار (چیزی شبیه
`-1001234567890`) و لینک دعوت رو هم اضافه کن:
```
REQUIRED_CHANNEL=-1001234567890
CHANNEL_INVITE_LINK=https://t.me/+xxxxxxxxxxxx
```

### مرحله ۳: ربات رو ادمین کانال کن
ربات باید توی اون کانال **ادمین** باشه، وگرنه نمی‌تونه عضویت کاربرها رو بررسی
کنه (ربات‌ها بدون ادمین بودن به لیست اعضا دسترسی ندارن).

### تغییر کانال بدون ریدیپلوی
هر وقت خواستی کانال رو عوض کنی، لازم نیست دوباره دیپلوی کنی؛ کافیه توی خود
ربات (با همون اکانتی که آیدیش توی `ADMIN_USER_IDS` هست) بزنی:
```
/setchannel @new_channel
/setchannel -1001234567890 https://t.me/+inviteHash
/setchannel off      ← غیرفعال کردن این قابلیت
/setchannel          ← نمایش کانال فعلی
```
این تغییر روی دیسک سرور هم ذخیره می‌شه، ولی چون فضای دیسک Railway/Render بین
دیپلوی‌های جدید پاک می‌شه، برای پایداری کامل بهتره بعد از تغییر با `/setchannel`،
مقدار `REQUIRED_CHANNEL` رو هم توی Environment Variables پلتفرم آپدیت کنی.| متغیر | توضیح | پیش‌فرض |
|---|---|---|
| `BOT_TOKEN` | توکن ربات از BotFather (اجباری) | - |
| `MAX_FILE_SIZE_MB` | حداکثر حجم فایل قابل ارسال | 50 |
| `COOKIES_B64` | محتوای base64-شده‌ی cookies.txt | - |
| `COOKIES_FILE` | مسیر فایل کوکی روی دیسک | - |
| `MAX_CONCURRENT_DOWNLOADS` | تعداد دانلود همزمان مجاز | 2 |
| `USER_COOLDOWN_SECONDS` | فاصله‌ی مجاز بین درخواست‌های هر کاربر | 8 |
| `MAX_DURATION_SECONDS` | حداکثر مدت‌زمان مجاز ویدیو | 7200 |
| `LOG_LEVEL` | سطح لاگ | INFO |
| `REQUIRED_CHANNEL` | کانال اجباری برای استفاده از ربات (خالی = غیرفعال) | - |
| `CHANNEL_INVITE_LINK` | لینک دعوت، فقط برای کانال خصوصی | - |
| `ADMIN_USER_IDS` | آیدی عددی ادمین‌ها (با کاما جدا) که می‌تونن `/setchannel` بزنن | - |

## نکته‌ی حقوقی

دانلود محتوا ممکنه با شرایط استفاده‌ی یوتیوب/اینستاگرام یا حق کپی‌رایت صاحب اثر
در تضاد باشه. این ابزار رو فقط برای محتوایی استفاده کن که اجازه‌ی دانلودش رو
داری (محتوای خودت یا محتوای با مجوز آزاد).
